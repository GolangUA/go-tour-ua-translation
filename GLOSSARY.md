# Go Tour українською: глосарій і правила термінології

Цей файл — **авторитетне джерело** для перекладу “A Tour of Go” українською в цьому репозиторії.  
Мета: узгодженість термінів, зрозумілість для читача й максимальна відповідність оригіналу.

Додаткові принципи перекладу (узгоджено):
- **Коментарі в Go-прикладах перекладаємо**.
- **Рядкові значення (`string`) у прикладах коду за можливості локалізуємо** (не змінюючи сенс прикладу).
- Go синтаксис/ключові слова/імена з коду лишаються англійською (оригінальні назви), але **під час першої появи терміну даємо пояснення українською**.
- Після першого пояснення не потрібно всюди дублювати український відповідник: можна надалі використовувати оригінальний термін (наприклад, `slice`).

---

## 1) Загальні правила

### 1.1. Ключові слова Go не перекладаємо
**Ключові слова мови Go** завжди лишаються в оригіналі (англійською) і, якщо згадуються в тексті, оформлюються в бектиках: `if`, `for`, `func`, `var`, `type`, тощо.

У пояснювальному тексті дозволено український опис поруч, наприклад:
- Ключове слово `defer` відкладає виконання…
- Оператор `:=` оголошує і ініціалізує змінну…

### 1.2. Код і ідентифікатори: що перекладаємо, а що ні
- Ідентифікатори (імена пакетів/функцій/типів/змінних), ключові слова та стандартна бібліотека **не перекладаються**:
  - `fmt`, `math/rand`, `Println`, `Pi`, `error`, `package`, `func`, `var`, тощо.
- Пояснювальний текст у слайдах — українською.
- **Коментарі в коді (`//`, `/* ... */`) перекладаємо** так, щоб вони залишались короткими і точними.
- **Рядкові літерали** (наприклад `"Hello, 世界"`) **можна перекладати/локалізувати**, якщо це не змінює мету прикладу (див. 1.5).

### 1.3. Збереження розмітки Tour
У `.article` файлах **не змінюємо**:
- посилання `[[...]]`,
- спеціальні директиви `.play ...`,
- префікси середовища на кшталт `#appengine:`.

### 1.4. Стиль звертання і тон
- Звертання до читача: **“ви”**, **“ваш/ваша/ваше”**.
- Перевага: короткі, технічно точні речення.
- Уникаємо “канцеляритів”; переклад має звучати природно для інженера.

### 1.5. “Перша згадка терміну” і подальше вживання
Коли в модулі/уроці вперше з’являється важливий термін:
- даємо українське пояснення,
- за потреби показуємо оригінальну назву в бектиках.

Рекомендований шаблон для першої згадки:
- **слайс (`slice`)** — …пояснення…
- **ґорутина (`goroutine`)** — …пояснення…

Після першої згадки в межах того самого модуля/уроку:
- можна **використовувати коротшу/оригінальну форму** (наприклад, далі писати `slice` без повторення “слайс”),
- але не жертвувати зрозумілістю: якщо текст читається гірше — краще лишити український відповідник.

---

## 2) Рекомендовані українські відповідники (канон)

Нижче наведені “канонічні” форми для **першої згадки** (або коли термін вводиться/пояснюється). Якщо ви бачите термін в оригіналі — використовуйте відповідник з цього списку і дайте пояснення.

Після першого введення терміну в межах уроку допускається надалі частіше вживати оригінальну форму (наприклад, `slice`, `goroutine`, `map`), якщо це не шкодить зрозумілості.

### 2.1. Паралельність і конкурентність
- **concurrency** → **конкурентність** (у заголовках також нормально “Конкурентність”)
- **parallelism** → **паралельність** (коли підкреслюється одночасне виконання)
- **goroutine** → **ґорутина**
- **channel** → **канал** (за першої згадки можна: “канал (`chan`)”)
- **buffered channel** → **буферизований канал**
- **deadlock** → **взаємне блокування** (можна уточнення: “deadlock” у дужках при першій згадці)
- **race condition** → **стан гонитви** (або “гонитва даних” залежно від контексту; узгодимо при першій появі)

### 2.2. Типи, значення, оголошення
- **type** (concept) → **тип** (але ключове слово `type` не перекладаємо)
- **built-in types** → **вбудовані типи**
- **type inference** → **виведення типу**
- **type conversion** → **перетворення типу**
- **assignment** → **присвоєння**
- **declaration** → **оголошення**
- **initializer** → **ініціалізатор**
- **zero value** → **нульове значення**
- **constant** → **константа**
- **untyped constant** → **нетипізована константа**
- **precision** → **точність**
- **literal** → **літерал**

### 2.3. Функції та методи
- **function** → **функція**
- **parameter** → **параметр**
- **argument** → **аргумент**
- **return value** → **повернене значення**
- **named return values** → **іменовані повернені значення**
- **naked return** → **порожній `return`** (можна: “`return` без аргументів”)
- **method** → **метод**
- **receiver** → **одержувач** (за першої згадки: “одержувач (receiver)”)

### 2.4. Структури даних і пов’язані поняття
- **array** → **масив**
- **slice** → **слайс** (за першої згадки: “слайс (`slice`)”)
- **map** (data structure) → **мапа** (за першої згадки: “мапа (`map`)”)
- **struct** → **структура** (ключове слово `struct` не перекладаємо)
- **field** → **поле**
- **pointer** → **вказівник**
- **address** → **адреса**
- **reference** → **посилання** (обережно: у Go немає “reference types” як у деяких мовах; вживати за змістом)
- **interface** → **інтерфейс**
- **implementation** → **реалізація**
- **satisfied implicitly** → **задовольняється неявно / неявно реалізується** (залежно від фрази)

### 2.5. Пакети, імпорт, експорт
- **package** → **пакет** (але `package` в коді не перекладаємо)
- **import path** → **шлях імпорту**
- **import** (noun) → **імпорт**
- **factored import** → **імпорт у дужках** (або “групований імпорт” — не змішувати в межах одного уроку)
- **standard library** → **стандартна бібліотека**
- **exported name** → **експортоване ім’я**
- **unexported name** → **неекспортоване ім’я**

### 2.6. Обробка помилок, керування виконанням
- **error** → **помилка** (тип `error` лишається як `error`)
- **panic** → **panic** (у тексті: “паніка (`panic`)” за першої згадки)
- **recover** → **recover** (у тексті: “відновлення (`recover`)” за першої згадки)
- **defer** → **defer** (у тексті: “відкладене виконання (`defer`)” за першої згадки)
- **switch** → **switch** (у тексті можна “оператор `switch`”)
- **case** → **case** (у тексті: “гілка `case`”)
- **select** → **select** (у тексті: “оператор `select`”)

## 3) Термінологічні правила для UI

UI рядки (наприклад у `static/js/values.js`) мають бути короткими й однозначними:

- **Run** → **Запустити**
- **Compile and Run** → **Скомпілювати і запустити**
- **Format Source Code** → **Форматувати код**
- **Reset Slide** → **Скинути слайд**
- **Options** → **Параметри**
- **Table of Contents** → **Зміст**
- **Previous** → **Попередня**
- **Next** → **Наступна**
- **Waiting for remote server...** → **Очікування відповіді від віддаленого сервера…**
- **Error communicating with remote server.** → **Помилка зв’язку з віддаленим сервером.**
- **Line Numbers** → **Номери рядків**
- **Syntax-Highlighting** → **Підсвічування синтаксису**

Примітка: у UI допускається “слайд” як усталене слово для Tour.

## 4) Як вводити новий термін

Якщо в оригіналі з’являється термін, якого тут немає:
1) Додайте його в цей файл у відповідний розділ.
2) Вкажіть один “канонічний” переклад.
3) За потреби — додайте коротку ремарку щодо вживання (коли перекладати, а коли залишати англійською).

## 5) Нотатки про спірні випадки (домовленості)

- “slice” → **слайс** (узгоджено; за першої згадки: “слайс (`slice`)”, далі можна `slice`)
- “goroutine” → **ґорутина** (узгоджено; за першої згадки: “ґорутина (`goroutine`)")
- “map” → **мапа** (перевага інженерної зрозумілості; за першої згадки додаємо `map`)
- “receiver” → **одержувач** (перший раз можна “одержувач (receiver)”)
- Коментарі в коді перекладаємо; рядкові літерали локалізуємо там, де це не спотворює приклад
